# 引擎适配（engines）—— 唯一允许出现引擎事实的地方

## 1. 边界

- `MANIFESTO.md`、`SKILL.md`、`styles/`、`craft/`、`surfaces/` **不含引擎命令、字体可用性、API、开关名**。
- 引擎事实只住本目录：某个引擎能做什么、不能做什么、会静默丢掉什么。
- 引擎适配器不改变审美判断。冲突时：**铁律 > 表面数字 > 引擎适配器**。引擎做不到的，换实现或降级并记录，不修改契约去迁就引擎。

## 2. 两条诚实规则

1. **没跑过就不写"支持"**。每条事实标 `tested`（有日期、版本、平台、复现步骤）或 `unverified`（来自公开文档 / 推测，不得作为承诺）。
2. **引擎升级即失效**。适配器是快照，不是真理；每次大版本升级后重跑该文件的测试清单，更新日期。超过 12 个月未复测的 `tested` 降为 `stale`。

## 3. 适配器结构（七节）

```markdown
# <引擎名> 适配器
> status: tested | unverified | stale · 最后核对：YYYY-MM-DD · 平台/版本

## 1. 适用范围          能产出什么表面、什么格式
## 2. 画布与单位        坐标系、尺寸、导出比例
## 3. 字体与字重        可用字族、字重陷阱、中文栈、回退行为
## 4. 布局与文本        容器、溢出、行高、自动布局的真实行为
## 5. 图像与图表        原生图表、SVG、文字层、分辨率
## 6. 导出与门禁        格式、字体嵌入、可编辑性、lint / 审核
## 7. 已知损失与绕法    做不到的事 + 合法替代 + 复测清单
```

## 5. 怎么新增一个适配器

1. 用该引擎做**同一页**：一个动作标题、一段导语、一张图、一个数据图、一个页脚。
2. 记录它实际产出的文件与渲染结果（截图），不是它宣称支持的。
3. 专测四件事：**字重是否被静默忽略、中文字体是否回退、文本是否溢出容器、文字是否可编辑**。
4. 写七节；每条能力标 tested / unverified；写清做不到时的合法替代（见 `surfaces/` 的占位与降级规则）。
5. 在 `../../SKILL.md §7` 已有 `engines/` 路由，无需改入口；在本文件 §4 加一行，并在 `../../EVOLUTION.md` 登记。

## 6. 反面清单

- 把某个引擎的组件名、开关名、CLI 命令写进 `surfaces/` 或 `styles/`。
- 把"文档说支持"写成"实测可用"。
- 用引擎的默认组件冒充设计决策（默认卡片、默认图表、默认图标）。
- 因为引擎做不到就降低可读性下限；正确做法是换实现、换素材或明确降级。
