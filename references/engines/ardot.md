# Ardot 适配器

> status: unverified · 最后核对：2026-10-25 · 无实测运行记录
> 本文件只写**公开能力层面的用法约束**，不写命令、API、内部开关。任何具体功能以你当前版本的界面为准；未实测前不得向用户承诺导出质量。

## 1. 适用范围

- 公开定位：AI 辅助的界面 / 视觉设计工具，可从自然语言或参考图生成可编辑设计稿，支持设计系统与设计交付。
- 适合：网页与 App 界面、落地页、组件与设计系统、从设计稿到代码的交接。
- 不适合：需要精确印刷控制的成品（转 `handbook.md` + 专业排版工具）、复杂数据图表的最终排版（图表代码绘制更可靠）。

## 2. 画布与单位

- 以 **1440 视口（内容 1296）** 为桌面基准；同时出 **768** 与 **390** 两个断点帧，不接受"自动响应式"口头承诺。
- 8px 空间网格；12 列 × 24 槽；边距 5vw（最小 24）；内容上限 1440（≥1600 视口才达到，列宽 98）。
- 设计稿单位用 px；交付代码时再由实现层转 rem，不在设计稿里混用。

## 3. 字体与字重（必须实测）

- 生成后第一件事：确认**实际使用**的字族，而不是你要求的字族。AI 设计工具常回退到系统默认。
- 中文文本中文字体放栈首；中英混排拆两个文本层各控字重（见 `slidep.md §3` 的同一条规律）。
- 字重只认实际字面；如果界面只提供 400/700，就不要在稿里写 300 或 900 的期望。
- 一个项目最多三个字体角色：展示、正文、标签/数字。默认不用 Inter。

## 4. 布局与文本

- AI 生成的默认倾向：圆角卡片、三等分功能块、居中 hero、图标墙、渐变按钮。这些都在硬地板上，生成后必须改写。
- 给 AI 的版面指令必须是**可计算的**：列跨度、边距、字号、行高、对齐方式、文本最大行宽。不要写"高级一点""留白多一些"。
- 文案必须**逐字给定**；不要让工具生成营销文案（会命中填充动词与假事实）。
- 生成后检查每个文本层：是否被截断、是否自动缩小、是否被转成图形、是否仍是可编辑文本。
- 组件实例允许；但页面结构不能由默认组件拼成。先有构图，再用组件实现。

## 5. 设计系统交接（本项目最重要的一节）

把 Folio 的决策写成工具能吃的 token 与规则，而不是审美形容词：

| 类别 | 交付内容 |
|---|---|
| 色彩 | paper / ink / signal 三值 + 中间调派生规则（墨的透明度）；语义色与图例；无独立灰 hex |
| 排印 | 字族栈（中文栈首）、四级阶梯、行高、字重轴、最小字号 |
| 网格 | 列数、槽、边距、基线、内容最大宽、断点 |
| 形状 | 圆角 **0**、阴影 **无**、描边 1px / 2px / 3px 三档 |
| 组件 | 按钮 / 输入 / 卡片 / 表格 / 导航的必要状态；状态不只靠颜色 |
| 动效 | 只允许工具性动效；≤200ms；只动 transform / opacity；尊重 reduced-motion |
| 素材 | 真实图片与来源；缺图时的合法占位（信号色块 + 说明），不用假 UI |

交付说明写清：哪些是设计决策，哪些是工具默认值。默认值不算决策。

## 6. 导出与验证

- 导出后**在浏览器实际打开**，在 1440 / 768 / 390 三个宽度截图核对。
- 检查：字体替换、文本溢出、图片裁切、对比度、焦点可见性、键盘顺序、语义标签。
- 设计转代码时，以设计稿的 token 为准；代码里出现的第四个色相、第二个圆角值、阴影都是偏离。
- 不能把"工具预览看起来对"当作验收；验收以真实渲染与交互为准。

## 7. 已知损失与绕法

**未实测，以下为风险清单，不是结论：**

- 精细网格与光学对齐可能被自动布局改写 → 关键页手工锁定位置，或导出后用代码实现。
- 字体可能被替换 → 交付前嵌入或改为可用字族，并重排换行。
- 图表可能只有默认样式（图例、网格、圆角）→ 数据图改用代码绘制，再放入版面。
- 复杂文字排版（避头尾、标点挤压、中西文间距）支持有限 → 重要文本在排版工具或代码中完成。
- AI 生成的内容可能含假数据、假 logo、假头像 → 一律替换为真实材料或明确标注的占位。
