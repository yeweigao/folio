# Apple + Developer style — the tool proving itself

**Invocation:** Apple + Developer — Make the page as a developer tool's front door is made: the tool seen working is the proof, the headline states the action, and the technical voice stays inside the proof; never a photograph hero, a gradient wallpaper or a second accent.

Software a developer, designer or team uses to make something: deployment platforms, issue trackers, databases, design canvases, workspaces. Its proof is neither a photograph nor a price but the tool at work; spoken in Apple, the gallery becomes a front door where the visitor sees the tool working before being asked to act.

- **The interface is the hero.** A deployment, an issue list, a table, a canvas, a document: readable, shown whole, letterboxed rather than cut at its frame. Never a lifestyle photograph or an abstract illustration.
- **The headline is the action.** A verb the software performs, stated once, above the proof.
- **The technical voice proves; it does not speak.** Mono, shortcuts, states and code appear where the tool is named or shown working; never as headline, tagline or body.

**Hands in this school.** One governs; the others visit as single moves.
- **Vercel — the developer's front door.** A light ground; gradient on the headline's verbs at hero scale; the product interface below as proof; mono for technical labels; a full pill for the marketing action, small squarish controls for tools. Suits deployment platforms and any claim that is an action performed by software. Never: a dark page, a gradient on a button or card.
- **Linear — the engineering document.** A dark canvas in surface steps divided by hairlines; one lavender accent for action and focus only; the interface in charcoal panels as hero; modest rectangular buttons. Suits issue trackers, workflows and queues. Never: a light section, a gradient wash, a pill.
- **Supabase — the database as proof.** One green as the only chromatic event against greyscale; tables and code shown working in dark blocks; soft rectangular buttons. Suits databases, backends and APIs. Never: a second accent, a hero without a table or code in it.
- **Figma — the canvas as rhythm.** A black-and-white core with pastel colour blocks as the page's rhythm; a variable sans at fine weight steps, tight tracking; mono uppercase labels; pill the only button; the canvas with collaboration cues as hero. Suits design tools and shared canvases. Never: one accent posing as the system, a saturated block where a pastel belongs.
- **Notion — the workspace as hero.** A deep navy hero band, a purple pill action, pastel feature cards, a neutral sans with modest buttons, a workspace as hero. Suits documents and team knowledge. Never: a white-only hero that loses the band, pastel cards as decoration rather than features.

**Apple keeps:** the single accent, weight as hierarchy, the change of ground as divider, one lead per screen.

**Test:** Cover the brand name: the interface still proves the claim, and the hand's philosophy still holds. Swap the hand: the same input becomes another brand, not the same page recoloured.

**Caricature:** a photograph hero for a tool; a gradient wallpaper; mono body copy; placeholder bars posing as an interface; two governing brands; a pill on every Linear control, or a square Vercel hero action.
