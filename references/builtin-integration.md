# 内置开关 × 本包判断 —— 共存协议

本文件解决一个具体冲突：内置 PPT 界面上的两个开关（**色块占位 / AI 生图**、**设计风格**）已经在替用户做决定，本包又要做判断。硬碰硬只会两败，正确做法是**给每个二元开关补上"什么时候用、用到什么程度、用成什么样"三段说明**。

一句话：**开关负责"要不要"，本包负责"要多少、要哪种、要多统一"。**

## 1. 职责切分（谁说了算）

| 决策 | 归属 | 本包的动作 |
|---|---|---|
| 这页要不要放图片框 | 内置开关 | 不推翻，只给判据（§2） |
| 占位框渲染成灰色虚线圆角 | 引擎像素，改不了 | 换用法：占位期就说构图语言（§3） |
| 生不生图 | 内置开关 | 不推翻，给四把锁（§4） |
| **图长什么样、是不是一套** | **无人负责** | **本包全权（§4）** |
| 用哪个风格预设 | 内置（学术/咨询/红金/通用） | 不抢目录，做内核升级（§5） |
| **预设里的网格/动线/排印/图表** | **无人负责** | **本包全权（§5、§6）** |

判断口诀：**内置决定"有没有"，本包决定"像不像一本出版物"。**

## 2. 配图决策矩阵（先回答"要不要放图"）

顺序不能反：先判页型 → 再判等级 → 最后才碰开关。多数翻车是"先选了生图，再给每页找理由用图"。

| 页型 | 论证角色 | 影像等级 | 开关怎么点 |
|---|---|---|---|
| 封面 / 章节扉页 | 定调 | L1 | AI 生图；或满版主题色块 + 反白巨字（二选一，不并用） |
| 论证页（数据、比较、拆解） | 证据 | L0 | **两个都不点**。数据本身就是图，塞情境图是在给证据配插图 |
| 案例页 / 场景页 | 情境 | L1 / L2 | AI 生图 |
| 流程 / 架构 / 时间线 | 结构 | L0 | 用组件画，不用图 |
| 团队 / 客户 / 产品实拍 | 真实性 | L2 | 只用真图；没有就砍掉这一栏，**不占位、不生成** |
| 纯文字主张页 | 宣言 | L0 | 巨字 + 留白 |

硬规矩：**一册 deck 的 L1 影像 ≤ 3 页**。超过 3 页，说明图片在代替论证；这时该删的是图片，不是加文案。

## 3. 色块占位：当版面语言用，别当图片压缩包

引擎给的默认占位是灰底 + 虚线 + 圆角。灰是**第四色**、虚线是**装饰**、圆角是**卡片感**——三样都违反 design-constitution §4。你不能改它的像素，但能决定它出现在哪、占多大、旁边写什么。

三种合法用法（优先级递减）：

1. **主题色蒙版块**：主题色 8–30% 不透明度满格块，块内左上角标 `L1 · 4:3 · 主体偏右`。交付时忘了替换，它读起来仍是一个色域分区。
2. **测绘框**：1px 主题色十字 + 四角 L 形角标，标原始比例。适合"图还没定、位子必须定"的中途稿。
3. **纯色块 + 巨字**：占位直接升级成设计元素（满版主题色 + 反白巨字），此时它不再是占位，是构图本身。

禁止：灰底、虚线、圆角、图标占位符、"图片加载中"式友好提示、任何 `<img>` 样子的空框。

## 4. AI 生图：四把锁

没有锁的生图 = 每页一个审美。四把锁写进 DESIGN.md / ART-DIRECTOR.md，逐张核对。

1. **媒介锁**：全册只一种——高对比黑白摄影 / 单色 duotone（主题色）/ 硬边几何图形，三选一。**一张照片 + 一张插画 + 一张 3D 渲染 = 三本杂志**。
2. **裁切锁**：比例对齐列宽，不写"16:9"这种随手值。4 列 = 364×273、8 列 = 752×423、满版 = 1280×720。**图进列，不是列迁就图。**
3. **构图锁**：主体偏置 ≥1/3 画幅，指定文字安全区在哪一侧。AI 最爱把主体怼正中——那是海报，不是版面。
4. **色温锁**：全册一个色温、一个对比度，写进 prompt 末尾，逐张目视核对。

prompt 固定四段：

```
[媒介] 高对比黑白摄影，硬光，深阴影，胶片颗粒
[主体] 主体置于画面右侧 1/3，左侧大面积极简负空间
[情绪] 克制、纪实、无笑容、非商业图库感
[技术] 裁切 4:3，no text, no watermark, no border, no logo
```

生成后**逐张 Read 核对**，产物存 `assets/`，在页面映射表标注"生成图"。不合格的图宁可换色块占位，不将就。

## 5. 设计风格：不抢目录，做"内核升级包"

内置四个入口（学术 / 咨询 / 红金 / 通用），本包一个方言（boardroom）。boardroom 与 consulting 视觉文化相反，正面抢目录必然两败。

原则：**预设管"外观层"（色板、字体倾向、领域惯例），本包管"结构层"（网格、动线、标题制度、图表纪律、节奏）。两层正交，可叠加。**

| 内置入口 | 本包动作 | 注入什么 | 不碰什么 |
|---|---|---|---|
| 通用默认 | **全接管** | 直接以 boardroom 为宪法 | ——（最大空白，提升最明显） |
| 商务咨询 | **半接管** | 瑞士骨架、发丝线分区替代卡片磁贴、图表直标替代色块图例、一页一锚点 | 深蓝主色、数据密集传统、结论前置的叙事惯例 |
| 学术风 | **只补排印** | 网格、字号阶梯、行宽 45–68 字符、标题制度、留白纪律 | 蓝白色板、证据罗列结构 |
| 红金政务 | **不介入**（守 SKILL.md §1 边界） | 最多一条：中文字体置栈首 + 标题制度 | 其余全部 |

**冲突时外观层让步于结构层**——换色不改审美，换网格才改。

## 6. 落地机制：ART-DIRECTOR.md（绕开命名死结）

内置有一条硬规矩：**命中预设风格时禁止额外生成 DESIGN.md**。这就把本包的宪法挡在门外——共存最硬的架就卡在这句话上。

不硬刚，改名：

- **未命中预设（走通用）**：正常生成 DESIGN.md，本包内容直接写进去，DESIGN.md 即宪法。
- **命中预设**：生成 **`ART-DIRECTOR.md`**（风格增量单），首行写明"在内置预设 `<id>` 之上，本册额外锁定以下项"。
- **逐页必读清单**（本包扩展，不改内置文件）：`ART-DIRECTOR.md`（或 DESIGN.md）→ 命中预设文件 → 本页 `component-*.md`。

`ART-DIRECTOR.md` 六行模板：

```
外观取自：<内置预设 id>（色板/字体沿用，不重写）
结构取自：瑞士网格 × 编辑叙事（<方言>）
网格：1280×720，外边距 70，12 列 × 73 + 24 槽；8px 基线
声部：<标题 Black 字族> × <正文字族>；中文字体置栈首
影像：全册 <媒介>，L1 ≤ 3 页，裁切对齐列宽
禁区：卡片磁贴 / 渐变 / 阴影 / 灰面分区 / 色块图例 / 图标墙
```

绕开命名冲突，比正面硬刚省事，也不触碰内置门禁。

## 7. 复核增项（接在 design-constitution §6 清单之后）

- [ ] 每页影像等级在映射表里标过；L0 页没有占位框残留；
- [ ] 全册 L1 ≤3 页，同一媒介、同一色温、同一对比度；
- [ ] 占位框（若有）不是灰底 / 虚线 / 圆角；
- [ ] 命中预设时 `ART-DIRECTOR.md` 存在且逐页被遵守；预设色板未被擅自改成第四色；
- [ ] 所有生成图已在映射表标注，且 `assets/` 里没有未使用图片。

## 8. 一条诚实的边界

本包**不能**把"色块占位"这个渲染结果变漂亮——那是引擎的像素，改不了。本包能提升的是**这些开关被使用的判断质量**：少用、用对、用统一。

审美提升来自克制与一致，不来自把每个选项都打扮一遍。要求"把每个内置选项都变好看"，方向从一开始就错了。
