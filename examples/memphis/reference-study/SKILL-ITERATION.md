# 从成品、迁移失败到 Skill 修改

本轮已实际修改十份 DESIGN.md 和主 skill。顺序是：复刻 28 件作品 → 反推 10 个世界 → 独立生成新内容 → 找到丢失的关系 → 先修各自 DESIGN → 新上下文复测 → 修改生成 DESIGN 的规则。最终十套采用样本的身份、构成、工艺评审均通过；完整结果与对照见 [批量迁移记录](batch-transfer/RESULTS.md)。

## 为什么不是一个孟菲斯模板

第二张拼图的九件作品得到八套系统：两张 Hackathon 共享一种构造，其余分别处理。第一张整套报告与第三张整套身份各是一套，共十套。这里按构造和身份分组，没有把同一拼图或同一流派名当成同一个世界，也没有认定未知作者的流派归属。

初稿并非完全不能迁移：两套身份已通过；其余八套有亲缘但丢失关键图形、尺度或构成。所有基线均保留，事实和工艺通过也没有被当作世界身份通过。

## 各自 DESIGN 修了什么

| 系统 | 留在系统里的修正 |
|---|---|
| 01 方砖报告 | 斜向短胖 X、多瓣放射块、圆角方叶的轮廓与内部比例；轻重字角色；小字合法配色 |
| 02 街区拼贴 | 粗颗粒格窗和随模块固定的纹理频率；同量级粗细中文、次级普通宽度英文 |
| 03 切割字形 | 连续大字场与分节拼接场；并列弯钩、带腰双碗和内孔；负形承接事实 |
| 04 俱乐部分区 | 裁切圆弧、楔形、鼓包、窄黑缝的变化关系；蓝区标签的可读配色 |
| 05 文化角色 | 圆眼、密排白点浅黑嘴、叠节／长触手的不同轮廓；模块延续到下部信息场 |
| 06 开发者空间 | 电蓝网格底、纸色标题窗、立体积木和扁平切形之间的前后关系 |
| 07 字母版面 | 字墙里的几何按整字格重造字形，避免字腔小贴片；独立数字圆盘使用达标近色值 |
| 08 森林角色 | 三层扁椭圆、顶部大白眼、黑白棋盘、粉色日期胶囊、黑地绿树的关系 |
| 09 等轴舞台 | 错位高窄体块、白桥、顶面与侧面共同排字；绿色面的文字改为合法黑字 |
| 10 模块景观 | 两种花的瓣、点、中心和叠层；短边推导的模块；普通竖版与窄长条分开重组 |

专有轮廓、比例和牌面关系留在对应文件。没有把十个案例的坐标或图形清单塞进通用 skill。

## 生成规则本身的验证

固定简报是 [tests/memphis-extraction.md](../../../tests/memphis-extraction.md)。旧版、新版、无 skill 三个独立上下文读取同一原始身份板，分别提取 DESIGN。匿名评审只看板、简报与文件，不知道版本。初次候选排名为新版 > 无 skill > 旧版；新版仅小幅领先，优势主要是可重画的内部比例与格式条件。评审指出重复实例数量不应写死，随后对此作了小幅澄清，并对最终文字重新生成文件复评。第二位全新匿名评审将最终新版列第一，旧版与无 skill 并列第二；仍指出个别局部配方和层级建议不宜成为恒定约束。两次生成和两次原始评审均保留。

这项实验判断的是文字交接，没有将三份输出各自再渲染成新作品，不能据此声称完整生成质量或平均可靠性提高。十套视觉迁移实测与此项提取实验是两份不同证据。

## 留存与边界

原输入、原作品、修订输入、修订作品分别冻结；旧版 skill 与匿名映射在 batch-transfer/archived。历史 extract_systems.py 默认保留已修订系统，显式参数才重建最初草稿，避免运行复现命令时抹掉评审修正。

原作字体与作者未确认。复刻使用授权替代字体和自建像素替代字，不是逐像素或原字库复原。当前每套只验证一个新简报，不能外推为所有画幅、内容长度或字形都可靠。
